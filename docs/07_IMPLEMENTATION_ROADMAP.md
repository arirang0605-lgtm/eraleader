# 단계별 구현 계획 및 게이트

각 단계에서 **실제 명령 실행 및 테스트 통과**를 완료의 기준으로 삼는다.

| 단계 | 내용 | 완료 조건 |
|---|---|---|
| P0 | 문서·상태·결정 기록, 원본 코드 파악 | 문서/경로 확인, 기존 파일 보존 |
| P1 | 독립 Python 패키지/CLI, Git, 설정·테스트 | clean install과 unit test |
| P2 | 한국 실데이터 1개 소스, 수집·원본 캐시·품질검증 | API/합법 샘플 수집, 재실행 안전 |
| P3 | PIT 저장소·시점별 종목군·분기 공시 | 미래 공시·종목 생존편향 회귀 테스트 |
| P4 | 범용 백테스트 엔진 비교·어댑터·baseline | 최소 재현 가능한 PIT baseline |
| P5 | 산업 분석과 개별 검증 | 산업 랭킹 및 PIT 평가표 |
| P6 | 기업 실적·경쟁력·모멘텀 + 개별 검증 | 종목 점수·사유·분해와 품질 보고 |
| P7 | 잠재/확정/약화/교체 상태 머신 | 이벤트 이력·중복 방지 테스트 |
| P8 | 미국 데이터 어댑터/대상 종목 확장 | 양국 동일 스키마 및 시장별 규칙 통과 |
| P9 | 통합 장기 백테스트·walk-forward·홀드아웃 | 선정 성능/비용 후 성과/실험 로그 |
| P10 | 웹 대시보드 MVP→상세 화면 | 실제 결과 조회·상태별 필터 동작 |
| P11 | 이벤트 알림·일/주/월 보고서 | 모의 전송·누락/중복 검증 |
| P12 | 배포/모니터링/선택적 외부 API | 재시작·복구·로그인·버전 호환 |

**실행 순서상의 유연성**: 최초 P4 테스트 기반을 P3 직후 배치하고, P5~P9 동안 매 모듈에서 자동 백테스트 실행. 간단한 화면은 P6~P7에도 병행 가능. 완성된 기능은 다시 만들지 않는다.

## 개발 루프
작은 작업 하나 선택 → 테스트 먼저 확인/추가 → 코드 수정 → 관련 모듈 테스트 → 실패 원인 해결 → 주요 단계 통합 테스트 → 파일·로그 저장 → PROJECT_STATE 업데이트 → Git 체크포인트.

## 첫 주기에 확보할 산출물
- 실행 가능한 CLI 1개
- 자료 1개 소스와 시점별 저장 구조
- 기본 기업/산업 스코어 + 가상 예제가 아닌 실제 종목 1회 분석
- 관련 PIT 테스트와 요약 백테스트
- JSON/CSV 출력과 웹 목록 1개
단계 진행에 맞춰 데이터 공급자 승인 등 외부 요건이 걸리면 독립 가능한 코드부터 개발.

## 반복 개발 종료 원칙
수정 2~3회로 해결 안 되는 동일 실패는 무한 재시도하지 않고 원인·시도 내용·차단 요건을 기록하여 다른 독립 모듈로 전환하거나 사용자에게 보고한다.
