# 운영·AI 토큰 절약·중단 복구

## 역할 분담
- Python/DB: 종목수천 개의 데이터 변환·지표 계산·백테스트·순위·알림/보고 배치.
- AI: 전략 설계, 차별화 가설, 실패 원인 분석, 코드 리뷰 및 선택적 해설.
- GitHub: 코드/문서/검증 상태 기록(민감키와 대용량 가격 원자료는 제외).
- 외장 SSD: 로컬 실데이터 저장·캐시·로그·결과. 별도 백업 정책 필요.

## 토큰 절감 규칙
1. 새 대화/세션은 README → AGENTS → PROJECT_STATE → 해당 작업 파일만 읽는다.
2. 프로젝트 전체 로그를 답변에 넣지 않고 error summary를 전달.
3. 불변 입력·가공 캐시와 증분 수집. 변경 모듈별 pytest/백테스트부터 실행.
4. 정상적인 일일 운영 중 LLM 호출 0회 목표. 특별한 해설을 요청할 때만 LLM 별도 호출.
5. 상태 전이를 이벤트로 저장해 새로운 사건만 알림/보고.
6. 표준 JSON 산출물로 다른 프로젝트 재사용. MarketOS에 소스 복사 금지.
7. 사용량·에이전트 한도와 시스템 기능 품질은 별개. 한도 소진으로 코드·데이터가 소실되지 않도록 구성.

## 장애 대응
- 실패 로그 수집 → 자동으로 단순 재시도(네트워크 오류 등) → 실패 지속 시 핵심 오류 저장 → AI 검토.
- 자동 재시도 횟수 제한, 비정상 수정 금지. 배치의 중복 실행은 idempotent.
- 네트워크 또는 PC/SSD 중단 이후 체크포인트(watermark)를 사용해 재개.
- 검증 결과는 run_id, 오류 코드, 파일 경로로 추적.
- 클라우드 배포 시 주기 백업·복원 시연·계정 보안·경비 한도를 별도로 결정.

## Git/상태 관리
- 코드 변경 전후 git diff, 변경 모듈 테스트, 커밋 기록.
- 상태: 실제 완료, 검증 대기, 미구현, 차단으로 나눠 기록.
- 마지막 성공 명령·입력 데이터 범위·코드 해시·다음 명령을 PROJECT_STATE에 남김.
- 대용량 데이터, 인증키, 로컬 접속정보를 GitHub에 올리지 않음.
