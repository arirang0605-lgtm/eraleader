## 2. 개발 단위 종료 필수 검사 — 기본 4개

1. **변경분 테스트:** 수정 함수·인접 경로의 자동 테스트를 통과한다. 전체 수천 테스트를 매 변경 때 재실행하지 않는다.
2. **실제 데이터 1건 E2E:** 가능한 공식 실수신 또는 이미 검증한 최신 공식 캐시로 `수집/검색 → 저장 → 화면·보고` 한 흐름을 실제로 실행한다. 해당 기능에 외부 API가 없으면 명시적인 오프라인 연구 스모크로 대체하고 별도 표시한다.
3. **현실적인 장애 1~2종:** 0행/중복/오래된 자료/공급자 연결 실패 등 해당 변경이 실제로 맞닥뜨릴 사례를 확인한다. 어떤 오류 때문에 화면이 비어 있고 사용자에게 어떻게 보이는지 확인한다.
4. **운영 표시·보존:** 기준일·신선도·N/A·연구/실전 구분, Git 변경 및 테스트 결과를 확인한다. 비밀키·원시가격·원장·미커밋 코드 보존, 공개 push 전 보안검사는 생략하지 않는다.

## 3. 언제 전체 통합·엄격 PIT 검증을 하는가

- **모듈 변경마다:** 위 4개 실사용 검사만 기본값. 기존 검증 증거를 재사용한다.
- **주요 기능 완성/출시 후보:** 한국·미국 실제 자료 연결, 대장주 후보→WATCH→웹·보고·알림의 전체 흐름, 중복 방지·복구, 눈에 띄는 자료 지연을 통합 검사한다. 전체 회귀도 이때 실행한다.
- **역사적 투자성과 주장·정식 매수/매도 신호·자동매매 연동 시:** 그 판단에 영향을 주는 **당시 정보 이용가능성(PIT), 상폐·기업행동·생존편향, 검증 데이터 편향**을 별도로 인증한다. 검증 전에는 성과/신호를 `연구용·미인증`이라고 표시하고 실전 자동주문은 허용하지 않는다. 공인 독립 최초게시 증빙이 없다는 사유만으로 현재의 날짜가 명확한 연구용 검색과 웹 보고 개발을 장기간 중단하지 않는다.
- **실운영 인수 전:** 예약 실행·기본 로그·복구, 지정된 운영 기간 관찰 및 백업 상태를 실제 테스트한다. 맥북/SSD 물리 장애 시험은 사용자 기존 결정대로 최종 단계.

## 4. 오류의 취급

- **사용자 작업 계속 + 주의 경고:** 당일 공급자 0행, 일부 기업 실적 결측, 과거 최초 게시시각 미인증, 휴장 캘린더 미확보, 전향 성과 만기 전. 새 매매신호·공식 확정·소급 백테스트는 여전히 금지.
- **해당 데이터 사용 차단:** 위조/훼손 SHA·불명확한 종목 동일성, 미래 데이터의 과거 판단일 혼입, 인증키 노출, 부정확한 실전 BUY/주문, 기존 원장 손상. 가능한 정상적인 과거 연구 결과는 별도 경고를 달고 계속 조회 가능하도록 한다.
- **낮은 우선순위:** 극단적 합성 실패 시나리오, 사업상 아직 없는 유료 원천 완전성 증빙, 동일 증거 반복 검사. 필요한 때 검증하되 기본 기능 개발을 막지 않는다.

## 5. 진행률과 완료 표현

- `구현·변경범위 시험 통과` / `실제 데이터로 실사용 확인` / `정식 성과·PIT 인증`을 **서로 다른 상태**로 기록한다.
- 기존 2026-10-13 **45/120 = 38%** 수치는 당시 엄격 기준의 과거 스냅샷이다. 이번 결정만으로 소급 점수를 올리지 않는다. 다음 운영 인수 현황부터 **실사용 체크리스트 충족 여부**를 먼저 보고하고 필요할 때 동일 분모 120점의 의미·변경 근거를 분리 공지한다.
- 향후 작업 보고는 **개발ID / 실제 작동한 기능 / 변경범위 테스트 / 사용자 화면·보고 확인 / 실제 미완료 / 다음 작업**을 우선한다. 불필요한 길고 중복된 감사 보고를 만들지 않는다.
