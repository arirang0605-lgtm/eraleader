# 6단계 개발 — 웹 대시보드·자동 알림·정기 보고

> 사용자 확정 요구: **웹 대시보드 + 자동 알림 + 정기 보고서** 모두 제공.
> 6단계는 4단계 상태/이벤트 + 5단계 검증 결과를 **한 데이터베이스**에서 읽어 전달. 기본 운영에 LLM 호출이 없어야 한다.

## 1. 수집/입력자료(새 시세 중복 수집 금지)
| 데이터 | 출처 | 화면/알림 활용 |
|---|---|---|
| 최신 점수·후보 랭킹 | 3단계 분석 DB | 국가별 산업 TOP5 / 잠재 TOP20 / 확정 TOP10 |
| 상태 변화 이벤트 | 4단계 event ledger | 신규·승격·약화·교체/성장가속 알림 |
| 발굴 이후 실제 수익 | 5단계/가격 이력 | 최초 후보일·누적수익·업종 초과수익 |
| PIT 검증·수집상태 | 2단계 품질/실행 메타 | 최신화 시각·결측·데이터 오류 배너 |
| 정기 집계 | 앞 단계 DB 산출물 | 일간/주간/월간 보고·PDF |

## 2. 웹 대시보드 설계
초기에는 **브라우저에서 열리는 반응형 읽기 전용 웹 UI**. Mac 로컬로 시작하고 이후 HTTPS/로그인을 갖춘 클라우드로 이전.

### 화면 구성
- 홈: 한국/미국 탭, 주도산업 TOP5, 확정 TOP10, 잠재 TOP20, 최근 신규/약화/교체 신호.
- 종목 목록: 시장/산업/상태/발굴일/점수 변화/거래대금 필터, 조회 기준일 표시.
- 상세: 종목점수(산업20·경쟁력20·실적25·RS25·수급10 **가설**), 주·월 추세, 공시/근거 링크, 결측 데이터/위험 요인, 최초 발굴일.
- 타임머신: 특정 과거 날짜를 선택해 당시 PIT 랭킹을 재생.
- 성과 페이지: 최초 선정 이후 1·3·6·12개월 실적, 국면별 hit rate/초과수익, 시장 기준 비교. 미검증 결과에 '연구용' 명시.
- 운영 페이지: 한국/미국 마지막 갱신시각(현지·KST), 공급자별 신선도, 실패한 수집/테스트 수, 최근 실행 run_id.
- 모든 화면은 같은 \`run_id\` 스냅샷을 조회하고 생성 중간 상태는 확정 화면에 표시하지 않는다.

## 3. 자동 알림 엔진
| 이벤트 | 트리거 | 메시지 |
|---|---|---|
| NEW_POTENTIAL | 4단계 WATCH→POTENTIAL | 국가/종목/점수/핵심 이유/선정일 |
| PROMOTED_CONFIRMED | POTENTIAL→CONFIRMED | 복수 조건·확정 근거 |
| LEADER_WEAKENING | CONFIRMED→WEAKENING | 악화 근거·데이터 기준시간 |
| REPLACEMENT_SIGNAL | incumbent/challenger 상대 우위 | 비교 근거·아직 매매 신호 아님 |
| GROWTH_ACCELERATION | 실적/산업/RS 동시 가속 | 근거 지표와 발표 시각 |
| DATA_FAILURE | 품질 실패·데이터 지연 | 해당 시장의 결과 보류 |

- 같은 \`event_id/channel\`은 **정확히 1번** 전송하는 목표(전송 실패 대비 상태 기록 및 중복 방지).
- \`alert_outbox\`: event_id, channel, template_version, status, attempt_count, sent_at, error.
- 알림 수신채널 후보: 텔레그램 bot, 이메일 SMTP/서비스, 향후 모바일 웹푸시. 사용자 선택 및 자격증명 필요.
- 휴장/중복 이벤트·다수 신호 발생 시 일괄 요약 가능. 중요 데이터 오류는 자동 투자 추천보다 우선 표시.
- 특정 수익률 또는 목표주가가 보장되는 것처럼 알림 표현 금지.

## 4. 정기 보고서
| 빈도 | 포함 내용 | 기본 형식 |
|---|---|---|
| 일간 | 국가별 최근 마감 기준 시장/산업·후보 순위 변화, 신규·약화 이벤트 | 웹/HTML + 이메일 선택 |
| 주간 | 주도산업 변화, 잠재20/확정10, 승격·교체 후보, 데이터 품질 | 웹/HTML, PDF 선택 |
| 월간 | 발견 이후 성과·실패 후보 포함, 업종초과수익, 모델 버전 변화, 백테스트 경고 | 웹/PDF/이메일 선택 |

보고서 생성은 결과 DB의 데이터와 템플릿으로 처리. 고급 자연어 해설이 꼭 필요할 때만 AI 옵션 별도 요청/비용 기록.
시장별 장마감·휴장일 고려하고 보고서의 갱신 기준일·생성시각 분리. 미국 장마감이 한국보다 늦는 시간차 때문에 한 장에 혼합 최신시각을 숨기지 않는다.

## 5. 실제 구현 기술(후보)
- Python 결과 API: FastAPI(선택), 읽기 전용 JSON, \`/api/v1/industries\`, \`/api/v1/leaders\`, \`/api/v1/candidates\`, \`/api/v1/events\`, \`/api/v1/performance\`, \`/api/v1/health\`.
- MVP UI: Streamlit(빠른 내부 검증) 또는 간단한 HTML+JS UI. 운영용 프레임워크는 배포/인증 요구 결정 후 확정.
- 저장: 읽기 전용 결과 DB + 별도 알림 outbox + 리포트 파일 storage.
- 스케줄: launchd/cron/CI 등 호스트 환경에 맞춰 선택; 맥북 전원 끄면 로컬 서비스 중단, 클라우드 배포 시 서버가 계속 작동.
- 접근 보안: HTTPS, 인증·권한, 비밀키 로깅 방지, 공급자 라이선스 준수. 외부 프로젝트 연결은 읽기 전용 API/버전 JSON.
- 클라우드/알림 채널은 아직 사용자 선택 전, 본 명세는 구현 완료가 아니다.

## 6. 모듈/파일 구조
\`\`\`text
src/eraleader/delivery/

tests/delivery/
\`\`\`

## 7. 구현 순서
- S6.1 최신 스냅샷과 과거 PIT 랭킹 조회용 read-only repository + mock response.
- S6.2 홈과 후보 상세, 데이터 최신화 시각, 모바일 반응형 구현.
- S6.3 최초 발굴 이후 평가/백테스트와 종목 선정 이유/위험/실패 이력 연결.
- S6.4 상태변경 outbox + 테스트 채널(중복/실패·재시도 검증).
- S6.5 일간·주간·월간 보고서 및 PDF 자동 생성, 동일 DB 검증.
- S6.6 인증/HTTPS 배포·백업/복원/스케줄·운영 점검(클라우드 여부 결정 후).

## 8. 수용 테스트
- 한국·미국 각 시장의 마지막 기준 시각과 결과의 run_id 동일.
- 목록 TOP10/20, 상태 변화와 기업 상세 점수의 내용이 일치.
- 0건 이벤트 시 불필요한 알림 발송 0.
- 실패 후 재시도에서 한 이벤트가 복수 발송되지 않도록 중복 키/상태 검사.
- 일/주/월 보고서는 데이터 변경 없이 재생성 시 동일 표·숫자; 임의 허위 수익률 없음.
- 외부 접속(운영 시)은 HTTPS 인증 후에만 가능하고 API 키 유출/데이터 재배포 위반 없음.
- **Gate S6:** 실제 데이터 end-to-end (수집→발굴→화면→알림→보고) 재생 실험 통과. 프론트엔드만 보이는 것은 '완성' 아님.
